## 1. Tóm tắt kết quả hoàn thành

Theo đúng kế hoạch MVP Vòng 2 (Mục I. BASE — Hạn chót: 16/10/2026), Thành viên A (Ly) đã hoàn thành toàn bộ khung xương kỹ thuật và nền móng chung cho toàn đội:

1. **3 Hợp đồng dữ liệu dùng chung (Contracts):**
   - Đặt tại `backend/src/contracts/` bằng TypeScript + Zod schema validation.
   - `telemetry.ts`: Bản tin cảm biến 5s/lần qua MQTT QoS 0, bổ sung trường `presence` (PIR) và `presence_age`, cờ `late` khi gửi bù.
   - `report.ts`: Phản ánh của SV, cơ chế che PII tự động, trả về mã tra cứu ngẫu nhiên (VD: `K7Q2-9XMA`), endpoint tra cứu tiến độ `GET /api/reports/track/:code`.
   - `ticket.ts`: Phiếu xử lý 6 trạng thái (`received -> assigned -> verifying -> handled -> responded -> closed`), 4 nguồn, 4 mức ưu tiên, hạn xử lý (SLA), 6 loại sự kiện AI (`cigarette, vape, steam, dust, spray, ambient`).
   - `zones.ts`: Danh mục 20 khu vực và 10 nút cảm biến KTX ĐHQGHN với toạ độ sơ đồ tầng.

2. **Cơ sở dữ liệu (Database & Prisma):**
   - `backend/prisma/schema.prisma`: Đầy đủ 9 bảng:
     - `Zone` (Khu vực)
     - `Device` (Nút cảm biến ESP32)
     - `Telemetry` (Bản tin đo lường)
     - `Event` (Sự kiện khói thuốc AI phân loại)
     - `Ticket` (Phiếu xử lý)
     - `TicketHistory` (Lịch sử audit log 6 bước)
     - `Report` (Phản ánh từ sinh viên)
     - `User` (Tài khoản người dùng 4 vai trò)
     - `Infographic` (Infographic tuyên truyền BQL đăng)
   - `backend/prisma/seed.ts`: Nạp sẵn dữ liệu khởi tạo chuẩn: 20 khu vực, 10 cảm biến, 4 tài khoản demo, 6 phiếu ban đầu đủ 6 trạng thái và SLA, 1 infographic mẫu.

3. **Hệ thống API & Realtime Socket.IO:**
   - Server Node.js + Express + Socket.IO chạy tại cổng `3001`.
   - `POST /api/auth/login`, `GET /api/auth/me`, `POST /api/auth/logout`: Đăng nhập 4 vai trò với tài khoản demo (`bql`, `catruc`, `phantich`, `bgk` / mật khẩu: `Demo@2026`).
   - `POST /api/reports`: Tiếp nhận phản ánh, tự động che SĐT/MSSV/Email bằng regex, gộp nguồn cùng khu vực trong 15 phút, tính toán SLA và phát realtime socket.
   - `GET /api/reports/track/:code`: Cho phép sinh viên tra cứu tiến độ và nhận phản hồi từ BQL/ca trực.
   - `GET /api/tickets`, `GET /api/tickets/:code`: Lấy danh sách phiếu (lọc `zone_code`, `status`), xem chi tiết và lịch sử audit log.
   - `PATCH /api/tickets/:code/status`: Chuyển trạng thái phiếu tuân theo máy trạng thái 6 bước (chặn nhảy cóc).
   - `GET /api/zones`, `PATCH /api/zones/:code/sensor`: Danh mục khu vực và trạng thái cảm biến.
   - `GET /api/stats/overview`: Chỉ số KPI cho Dashboard.
   - `GET /api/infographics`, `POST /api/infographics`: Quản lý infographic tuyên truyền.
   - `GET /api/health`: Healthcheck dịch vụ.

4. **Kiểm thử tự động (Tests):**
   - `backend/tests/contracts.test.ts`: Kiểm tra toàn bộ hợp đồng dữ liệu, che PII, sinh mã, máy trạng thái và SLA.
   - `backend/tests/api.test.ts`: Kiểm thử HTTP end-to-end các API backend.

## 2. Hướng dẫn chạy cho các thành viên

Chỉ cần một lệnh ở thư mục gốc:

```bash
# 1. Cài đặt thư viện
npm install

# 2. Chạy cả Backend API và Dashboard Admin song song
npm run dev
```

- **Backend API:** `http://127.0.0.1:3001`
  - Healthcheck: `http://127.0.0.1:3001/api/health`
  - Danh mục khu vực: `http://127.0.0.1:3001/api/zones`
  - Danh sách phiếu: `http://127.0.0.1:3001/api/tickets`
- **Dashboard Admin (Cúc):** `http://127.0.0.1:5173`
- **Tài khoản thử nghiệm:**
  - `bql` / `Demo@2026` (Ban quản lý)
  - `catruc` / `Demo@2026` (Ca trực)
  - `phantich` / `Demo@2026` (Phân tích)
  - `bgk` / `Demo@2026` (Khách / Ban Giám Khảo)

### Kiểm thử phản ánh từ Sinh viên (Thành viên B)

Gửi thử một phản ánh qua lệnh:

```bash
curl -X POST http://127.0.0.1:3001/api/reports \
  -H "Content-Type: application/json" \
  -d '{
    "zone_code": "B5-CTD",
    "type": "smoke_now",
    "ongoing": true,
    "emergency": false,
    "note": "Có mùi khói ở chiếu nghỉ tầng 5, SĐT tôi 0912345678",
    "device_token": "anon-device-token-1234"
  }'
```

Kết quả trả về:
```json
{
  "tracking_code": "K7Q2-9XMA",
  "status": "received",
  "ticket_code": "SF-261016-043",
  "message": "Phản ánh đã được tiếp nhận thành công"
}
```

Sinh viên tra cứu trạng thái:
```bash
curl http://127.0.0.1:3001/api/reports/track/K7Q2-9XMA
```

## 3. Hướng dẫn tích hợp cho từng thành viên

- **Thành viên B (Mạnh - Web App SV):**
  - Sử dụng API `POST /api/reports` để gửi phản ánh khi quét mã QR.
  - Lưu `tracking_code` vào `localStorage` của trình duyệt để hiển thị ở tab "Đã gửi" và trang "Tra cứu" qua `GET /api/reports/track/:code`.
  - Hiển thị danh sách infographic từ `GET /api/infographics`.

- **Thành viên C (Cúc - Dashboard):**
  - Dashboard đã tương thích 100% với hợp đồng API của A. Khi chạy `npm run dev`, dashboard tại `5173` tự động kết nối API `3001` qua proxy hoặc Socket.IO.
  - Sử dụng `PATCH /api/tickets/:code/status` khi ca trực bấm "Tiếp nhận", "Đang đến", "Đã xử lý", "Phản hồi".

- **Thành viên D (Đức - IoT & Simulator):**
  - Phát bản tin telemetry theo schema trong `backend/src/contracts/telemetry.ts` (đặc biệt chú ý trường `presence` và `presence_age`).
  - Có thể cập nhật trạng thái cảm biến trực tiếp qua `PATCH /api/zones/:code/sensor`.

- **Thành viên E (Hà - AI Detect):**
  - Module `packages/detect` import kiểu dữ liệu `Telemetry` từ `backend/src/contracts/telemetry.ts` để phân tích ngưỡng phát hiện tầng 1 và tầng 2.
