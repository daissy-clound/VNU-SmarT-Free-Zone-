## Chạy bản D2

Yêu cầu Node.js từ 22.12 trở lên, npm. Chạy ở thư mục gốc:

```sh
npm ci
npm run dev
```

- Dashboard: `http://127.0.0.1:5173`.
- API tích hợp: `http://127.0.0.1:3001`.
- Tài khoản cục bộ: `bql`, `catruc`, `phantich`, `bgk`; mật khẩu chung **`Demo@2026`**. Chỉ dùng cho máy chủ thử cục bộ, không dùng để triển khai công khai.
- Dữ liệu khởi tạo có 6 phiếu `SF-DEMO-*`, đủ 6 trạng thái, 4 nguồn và một phiếu quá hạn. Phiếu mới có mã máy chủ cấp.
- Root workspace hiện chỉ bật `frontend/admin`; A/B bổ sung backend/student-app khi có package hoàn chỉnh. `package-lock.json` là lockfile của bản bàn giao, dùng `npm ci` để tái lập.

Mở trang **Phiếu**, sau đó tại terminal thứ hai:

```sh
npm run report:demo -- B5-CTD
```

Phiếu tại B5-CTD tự xuất hiện, không tải lại trang. Gửi lại trong 15 phút có thể gộp vào phiếu đang mở cùng khu vực. Lệnh này mô phỏng request từ B; không phải xác nhận rằng B đã thực hiện nghiệm thu.

## Hợp đồng API bàn giao A/B

Định nghĩa và kiểm tra runtime đặt tại `backend/src/contracts/`. Frontend không tự tạo phiếu hoặc tự cấp quyền.

| Phương thức | Đường dẫn | Request / response |
| --- | --- | --- |
| POST | `/api/auth/login` | `{ username, password }` → `{ token, user: { id, name, role } }` |
| GET | `/api/auth/me` | Bearer token → `{ user }` |
| POST | `/api/auth/logout` | Thu hồi Bearer token và ngắt socket tương ứng |
| GET | `/api/zones` | `{ items: Zone[], coordinates_status: "provisional" hoặc "approved" }` |
| GET | `/api/tickets` | `{ items: Ticket[] }`; toàn bộ danh sách được phép đọc, sắp mới nhất trước |
| POST | `/api/reports` | Payload theo mục 4 → HTTP 201 `{ tracking_code, status: "received" }` |

`GET /api/tickets` có thể nhận `status`, `zone_code` trên máy chủ thử. Dashboard D2 tải toàn bộ danh sách được phép đọc rồi lọc/phân trang phía client; nếu A bổ sung phân trang API cần sửa adapter để không bỏ sót phiếu.

```json
{
  "code": "SF-261016-001",
  "zone_code": "B5-CTD",
  "source": "report",
  "priority": "normal",
  "status": "received",
  "created_at": "2026-10-16T14:00:00Z",
  "updated_at": "2026-10-16T14:00:00Z",
  "due_at": "2026-10-16T14:15:00Z",
  "assignee_id": null,
  "presence": null
}
```

- `source`: `sensor | report | both | emergency`; `priority`: `low | normal | high | urgent`.
- `status`: `received → assigned → verifying → handled → responded → closed`.
- Thời gian ISO 8601 có timezone; `due_at` do máy chủ quyết định. Dashboard không tự tính SLA nghiệp vụ. Máy chủ thử dùng 15 phút chỉ để kiểm tra hiển thị.
- `presence`: `true | false | null`. Trạng thái thiết bị: `normal | suspected | offline | unknown`.
- Socket.IO mặc định `/socket.io`, xác thực handshake `{ auth: { token } }`. Server phát `ticket:created`, `ticket:updated`, `zone:updated` sau khi lưu thành công; frontend nhận sự kiện rồi tải lại API.
- Token lưu trong `sessionStorage`, gửi qua Bearer header, không đặt trong URL. Reload xác thực lại qua `/auth/me`; HTTP 401 quay về đăng nhập. Mất mạng giữ dữ liệu cũ kèm nhãn, nút thử lại và thời điểm đồng bộ.

Payload B có thể gửi qua `POST /api/reports`:

```json
{
  "zone_code": "B5-CTD",
  "type": "smoke_now",
  "ongoing": true,
  "emergency": false,
  "note": "Mùi khói ở chiếu nghỉ",
  "device_token": "anon-test-b-001"
}
```

Máy chủ thử không lưu ghi chú hay danh tính trong phiếu; token thiết bị chỉ ở RAM để giới hạn 3 lần/10 phút. Mã tra cứu ngẫu nhiên được trả cho B nhưng chưa có endpoint tra cứu. Các nghiệp vụ che thông tin, lưu bền, SLA, gộp nguồn đầy đủ thuộc backend A.

Để nối A: sao chép `frontend/admin/.env.example` thành `.env`, đặt `API_PROXY_TARGET` tới URL của A rồi chạy lại Vite. Production đặt `VITE_API_URL` hoặc reverse proxy cùng origin cho `/api` và `/socket.io`; hosting phải fallback các đường dẫn SPA về `index.html`. Không chạy `dev:api` khi thử máy chủ chung.

## Kiểm thử và nghiệm thu

```sh
npm run typecheck
npm run build
npm test
npx playwright install chromium
npm run test:e2e
npm run assets
```

Kiểm thử API dùng server thật trên cổng tạm. Kiểm thử trình duyệt tự chạy API/Vite, gửi phản ánh HTTP rồi chờ hàng phiếu xuất hiện qua luồng realtime; kiểm tra bộ lọc, chọn SVG bằng bàn phím, đăng nhập lại sau reload, menu/URL theo vai trò, bố cục điện thoại, lỗi mạng và phiên hết hạn. Kết quả kiểm thử cuối ghi trong `docs/nhat-ky.md`.

Khi chuyển sang máy chủ chung ở bước tiếp theo:

1. A cung cấp URL, tài khoản và danh mục toạ độ đã duyệt, đối chiếu hợp đồng trên.
2. C nối dashboard tới URL đó; B gửi phản ánh từ ứng dụng SV của B.
3. Đối chiếu mã/khu vực/nguồn/trạng thái trên dashboard, kiểm tra không cần tải lại trang.
4. Ghi thời gian, URL môi trường, mã phiếu và ảnh/clip làm bằng chứng; A/E xác nhận bàn giao.

## Bàn giao E và phần tiếp theo

Thay ba nút ca trực đang vô hiệu hoá bằng thông báo chỉ xem, tránh thao tác không có kết quả.

E có khung `frontend/admin/src/pages/analytics/Analytics.tsx`, cùng wireframe 04 cho bản đồ nhiệt, minh bạch thuật toán và báo cáo tuần; D nhận khối dự báo/tuần tra. Không hiển thị số liệu đánh giá khi chưa nhận đầu ra.

Tham chiếu kỹ thuật đã đối chiếu: [Ant Design với Vite](https://ant.design/docs/react/use-with-vite/), [xác thực và tuỳ chọn Socket.IO client](https://socket.io/docs/v4/client-options/).
